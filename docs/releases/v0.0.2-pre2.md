## Install

```bash
sudo apt install ./dist/anvil_0.0.2~pre2-1_amd64.deb
anvil /path/to/your/project
```

To remove completely: `sudo apt remove --purge anvil`.

## New in this pre-release: dependency intelligence

Opening a C++ project used to show `'header' file not found` whenever a
dependency lived outside the workspace. clangd runs in a bubblewrap sandbox that
only saw `/usr`, the project, and its private cache, and VS Code solves the same
problem by asking you to edit `includePath` by hand. Anvil now does it for you:

1. **Find every compile database.** `compile_commands.json` in the project root,
   `build/`, `out/`, `.build/`, `cmake-build-*`, `build-<name>`, and colcon's
   `build/<package>/` are merged into one cache copy with absolute paths and
   passed to clangd through `--compile-commands-dir`.
2. **Derive include roots.** `-I`, `-isystem`, `-iquote`, `-idirafter`, and
   `--include-directory` are read as data; relative paths resolve against the
   compile command directory.
3. **Mount them read-only.** Roots under `/usr/local`, `/opt`, and non-sensitive
   directories under `$HOME` (deps, SDKs, sibling checkouts, colcon
   `install/`) are bind-mounted read-only in the sandbox automatically.
4. **Ask only when necessary.** A root such as `/srv/sdk` produces a banner with
   the exact path; one click adds it to `lsp.includePaths`, restarts clangd, and
   the choice persists.
5. **Protect secrets.** `.ssh`, `.gnupg`, `.aws`, `.azure`, `.kube`, `.config`,
   `.password-store`, `.pki`, browser profiles, `.docker`, `.npm`, `.netrc`,
   keyrings, and credential stores are never mounted and never suggested. `/etc`,
   `/root`, `/proc`, `/sys`, `/dev`, `/run`, and `/boot` are reserved.
6. **Query the compiler.** The compiler recorded in the compile database is
   passed via `--query-driver`, so GCC/Clang built-in include paths resolve
   inside the sandbox.

The merge and index also moved into the writable private cache, which removes
`Failed to create directory …/.cache/clangd/index` errors on a read-only
workspace.

### What it looks like

- A project with `-isystem $HOME/deps/include`: zero warnings, no setup.
- A project with a dependency in `/tmp/build-deps`: a banner naming the folder;
  one click fixes it.
- A project pointing at `~/.ssh`: refused, unresolved, and recorded in the audit
  log.

## New settings

- `lsp.includePaths` — up to 16 absolute dependency roots, explicit consent for
  locations outside automatic prefixes.
- `lsp.queryDriver` — optional compiler path for system include discovery;
  empty means "use the compiler from the compile database".

Both are validated in the core and at the IPC boundary.

## Known limitations

- Dependencies outside `/usr/local`, `/opt`, and `$HOME` need one click; this is
  deliberate so project data cannot widen the sandbox on its own.
- Compile databases must already exist; Anvil does not run CMake/colcon to
  generate them (Phase 3).
- `setup.bash`/ROS environment sourcing is still IMP-005.
- Startup (~0.85 s) and full-stack memory remain above target (0.0.3 work).
- Native GTK dialogs follow the system locale, not the in-app language.
- `lintian` is unavailable in the reference environment.
