# Anvil IDE 0.0.1

**First experimental release.** A C++-first IDE with clangd intelligence, a
native C++ core, and a Monaco editor inside the system WebView. Ubuntu 24.04,
x86_64.

> This is a 0.0.1 experiment, not a daily-driver replacement. Build, debug,
> terminal, Git write operations, plugins, and AI are intentionally absent and
> marked as later phases in the UI.

## Highlights

- **Real C++ intelligence** — clangd hover, completion, go-to-definition,
  find references, signature help, formatting requests, and diagnostics.
- **Sandboxed language server** — clangd runs under bubblewrap + seccomp with a
  read-only workspace, a private cache, no network, and a deny-list for ptrace,
  mounts, keyring, BPF, io_uring, and non-UNIX sockets. Release builds fail
  closed if the sandbox is unavailable.
- **Native C++ core** — workspace jail, filesystem, inotify watcher, settings,
  recent projects, and LSP lifecycle live in a separate C++20 process behind a
  validated JSON-RPC 2.0 contract.
- **No Electron, no bundled Chromium** — the `.deb` is about 1.35 MiB; the
  system WebKitGTK view renders the Monaco UI.
- **No telemetry, no remote content** — strict CSP, local assets only, and an
  append-only security audit log with redaction.

## What works

- Open a real folder; lazy file tree with inotify refresh; create, rename, and
  delete files and folders.
- Tabs with dirty state, crash-safe workspace state restore, atomic saves, and
  external-change detection with Reload/Overwrite.
- Monaco with the Anvil dark theme, C++ highlighting, minimap, bracket
  colorization, per-file models, and view-state restore.
- Problems panel on real clangd diagnostics with click-to-navigate.
- Output panel, command palette (30+ commands), quick open by file name,
  settings, security status, and about dialogs.
- Status bar: branch, problem counts, cursor, indentation, EOL, encoding,
  language, clangd state, and sandbox state.
- Native folder/file dialogs; workspace selection mediated by the shell.
- Read-only Git branch indicator from `.git/HEAD` (no Git commands executed).

## Install

```bash
sudo apt install ./anvil_0.0.1-1_amd64.deb
anvil /path/to/project
```

Recommended packages (APT installs them as Recommends):

```bash
sudo apt install bubblewrap clangd-18 gdb cmake ninja-build git
```

The package installs a minimal AppArmor profile for `/usr/bin/bwrap`
(`/etc/apparmor.d/anvil-bwrap`) so bubblewrap can create user namespaces on
Ubuntu 24.04. If your environment blocks user namespaces entirely, the language
server is refused rather than run unsandboxed; the Security Status dialog shows
the reason and the exact sandbox error.

## Security

- Workspace-scoped relative paths only; symlink escapes rejected after
  canonicalisation; rename/delete operate on links without following them.
- No `system()`, `popen()`, or `sh -c` anywhere; all processes use argv arrays.
- Workspace roots are allowlisted by the native shell: only the CLI path,
  native-dialog choices, and recent projects can become a workspace.
- Secrets are not stored in this release; logs and language-server output pass
  through redaction.
- Full analysis: `docs/security/threat-model.md`.

## Known limitations

- **Startup ~0.85 s**, above the 500 ms goal. WebKitGTK startup and the Monaco
  bundle dominate; a lazy bundle is planned.
- **Memory**: idle welcome ~255 MiB PSS (within the 300 MiB goal by PSS), but a
  full stack with clangd exceeds it; clangd's background index is the largest
  contributor.
- **No build/run, debugger, PTY terminal, Git staging/commit, plugins, or AI.**
  Those panels show a phase notice; the run dialog's Start button is disabled.
- The UI is English-only; localization is scheduled for 0.0.2.
- The UI is a single classic bundle because `file://` cannot reliably load lazy
  ES-module chunks; a custom URI scheme is planned.
- The reference build container blocks user namespaces, so the production
  sandbox path could not be executed there; sandbox argv and deny rules are
  unit-tested, and the sandbox was verified on real clangd through the
  documented development override. Desktop verification is still required.
- `lintian` and a clean-VM `apt install` were not available in the reference
  environment; run them before treating this as a public release.
- The local APT repository in `dist/` is signed with a **demonstration** key.
  Do not use it for public distribution.

## Package contents

- `usr/bin/anvil` — GTK3/WebKitGTK shell
- `usr/lib/anvil/anvil-core` — C++20 core
- `usr/share/anvil/ui/` — React/Monaco bundle
- Desktop entry, AppStream metadata, 256/512 px + SVG icons
- `usr/share/doc/anvil/` — README, architecture, build guide, threat model,
  benchmarks, release checklist, SBOM, ADR
- `etc/apparmor.d/anvil-bwrap` — bwrap user-namespace profile

## Upgrade / uninstall

```bash
sudo apt remove anvil      # keeps ~/.config/anvil
sudo apt purge anvil       # still keeps ~/.config/anvil (user data)
```

Anvil never deletes your settings, recent projects, or workspace state.
